# Project

What every agent needs to find and understand the learner's work. Fill it in
when the learner defines or brings a project, and update it when something
changes. Record each decision as the learner's, in their words where possible.

- **Track:** build | understand
- **Lane:** direct agents (judge behaviour, don't read code) | write code (read
  and write some code) | both

- **What it does and who it's for:**
- **Where it lives:** `app/` in this workspace, or a path or repository URL.
  Note if it's its own Git repository.
- **Stack, and why it was chosen:**
- **Build agent:** the tool the learner builds with, such as Claude Code or

- **Visibility:** public practice in `app/`, or a private repository

Plan your app decisions:

- **P.1 Build or not, and on what:** the chosen option, the alternatives, the
  costs and the stop rule
- **P.2 Data rules:** the data categories, each rule and where it came from, who
  was asked. Until real data is approved, only synthetic data.
- **AI tool approval:** which AI tools the organization approves for this work
  and data, and who confirmed it
- **P.3 Users and access:**
- **P.4 Owner, backup and signs it should move to IT:**
- **P.5 First-version outline:** path to the learner's one-page outline, such as
  `.learning/OUTLINE.md` or a file in the project repository

## Understand track

- **Role and interest:** product manager | risk and control | other; what they
  want to follow
- **Repository followed:** URL, default branch, and where the local clone lives
  (outside the course folder)
- **Access:** all that apply: read on GitHub, local clone, may run locally, test
  environment, may comment, may open pull requests
- **Approved AI tools:** which tools the organization approves for this code,
  and who confirmed it. Until confirmed, practise on the course's packets.
- **Data rules:** what data the app holds, what must never be copied into
  prompts, notes or `.learning/`
- **Environments allowed:** names and what they may affect. Never production.
- **Practice repository:** URL of the learner's own practice repository for
  issues and pull requests
- **Signs off on this system?:** yes | no. If yes, practise authoring pull
  requests in the practice repository, not on this system.
