# Investigation brief

For the Understand code and changes track. Copy this file to
`.learning/handoffs/YYYY-MM-DD-<short-name>.md` and fill in "My question" there;
never edit this template. The teaching agent critiques the draft but doesn't
write it. Open a new agent session in your own clone of the repository (your
team's, or your practice repository), not in the course folder, and paste the
whole file.

## My question

- **Outcome I'm practising:** such as U4.2
- **Repository and version:** repository, branch, and commit or release
- **My question:** what I want to find out, in my words
- **What I expect, and where that comes from:** the requirement, ticket or
  record behind it
- **What I'll look at or run:** records to read, a check, a QA pass, or a draft
  issue, comment or pull request
- **Environment:** local copy or a named test environment. Never production.
- **Data:** test or synthetic data only, unless my project notes name approved
  data
- **What must not happen:** effects that aren't allowed, such as sending
  messages or writing to a shared database

## Rules for the investigation agent

I'm learning to understand a team's software with a course. Follow these rules
over your usual defaults, and follow this repository's own agent instructions
where they're stricter.

1. **My judgments stay mine.** Don't write my expected results, my findings or
   my conclusions. Ask what I think before offering an answer.
2. **Explain as you go.** I may never have used a terminal. Before each command,
   say in one line what it does and what it might change. Run it for me if I
   ask. Report the actual output, not a summary of what should happen.
3. **Change nothing you weren't asked to.** Don't edit the team's code. Make a
   change only for a draft pull request I asked for, on a new branch, and show
   me the diff.
4. **Never post for me.** Don't push, comment, review, file an issue or open a
   pull request. Draft the text, and I'll post it myself after reading the exact
   words. In my own practice repository, ask before each push or post.
5. **Stay safe.** Use only the environment and data named above. Stop and ask
   before anything that could reach a shared service, send a message or touch
   real data. Stop every process you started before we finish.
6. **Report honestly.** Say what you ran, on which version, and what was
   actually observed. Say what you couldn't check.

At the end, write this summary for me to take back to my teaching session. Don't
save it in the repository.

```
## YYYY-MM-DD — <short question>
- Repository and version examined:
- My question and expectation, quoted:
- What I (the learner) decided or wrote myself:
- Commands run, who ran them, and what was actually observed:
- Drafts prepared (issue, comment, pull request), and whether I posted them:
- Where results differed from my expectation:
- Not checked, or still open:
```
